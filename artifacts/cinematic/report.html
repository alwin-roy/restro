RESTRO · IMPLEMENTATION REPORT · 25 NOVEMBER 2026

Beyond the Taste.

The existing yellow-and-white homepage and cartoon hero have become a continuous, scroll-controlled restaurant film with transparent editorial navigation, ivory serif typography, architectural borders and restrained champagne accents. Existing React Server Components, forms, data, carousel reducers, menu routes and local review storage remain in place. No production dependencies, APIs or databases were added.

Implementation and design

The homepage mounts one fixed decorative video beneath a contrast gradient, architectural frame and content. It never plays or loops automatically. Native scrolling drives paused video seeking through measured section anchors. The hero contains the requested copy, outlined menu action and three working navigation cards. The mascot is no longer imported by the homepage; all its components, assets and preparation scripts remain intact.

Opaque homepage sections, white cards and large yellow backgrounds were replaced with transparent surfaces. Cards use 6–8px corners, approximately 20% ivory borders and subtle dark tints; forms use stronger tints and dialogs use an almost opaque smoked surface. Backdrop blur is confined to the small header. Menu and About use a single static, video-derived interior image instead of loading the film. CSS accounts for Next.js retaining hidden pages during navigation.

Controller and responsive behavior

The controller caches section positions and linearly interpolates timestamps between them. A longer mobile category grid therefore stays within its kitchen-to-food scene range. ResizeObserver, resize, font readiness, page restoration, hash navigation, focus restoration and dialog closure invalidate geometry. One passive scroll listener schedules work through requestAnimationFrame; there is no idle animation loop or per-frame React state update.

While a seek is in flight, new scroll positions replace the target; seeked applies the latest target. Requests are clamped to valid duration and filtered at one-frame precision. Forms and open dialogs suspend seeking, as do hidden tabs. Cleanup removes listeners and observers, cancels pending animation work and unloads the source on route suspension. Initial loading and errors retain a scene fallback. The poster is hidden only after a valid frame is decoded.

Only one asset is selected at activation: mobile below 768px, desktop otherwise. Resizing recalculates layout without downloading a second video; reloading selects the asset appropriate to the new viewport. Mobile uses cover cropping with a 60% horizontal focal position during kitchen footage. Hero cards stack compactly on phones; categories remain 1/2/3 columns; reviews remain 1/2/3; contact retains the desktop 32/68 layout. Minimum form input text is 16px. The mode control respects safe areas.

Reduced motion and Save-Data default to static mode. A persisted, explicit mode choice overrides the automatic default. Static mode unloads the video source and changes between extracted scene images while retaining the full layout and all interactions. No-JavaScript visitors retain the opening image and all server-rendered content.

Functional and responsive regression results

  • No document overflow at 320, 360, 375, 390, 430, 768, 1024, 1440 and 1920px in Chromium.
  • Mobile navigation opens, closes with Escape, returns focus and retains inert hidden links. Expanded navigation overlays content without changing the timeline geometry.
  • Reservation invalid submission displays current validation errors and focuses Full Name; clock dialog opens, cancels and preserves the selected time.
  • Enquiry invalid submission displays all expected errors and focuses Your Name. Neither form sends data or stores submissions; confirmation copy now accurately describes a local preview.
  • Review dialog opens and dismisses with Escape. Existing pure tests verify validation, local persistence, carousel boundaries and responsive visible-card counts. Existing offer and review carousel logic is unchanged.
  • Menu overview, Shawarmas products and About were inspected. All nine category routes are generated and all 48 catalog entries, images, IDs and integer prices remain. Sample and illustrative-content labels are visible.
  • Section navigation seeks to the relevant scene; reservation refresh restored around 34.52s. Bottom settled at 55.79s (the last decodable frame); Back to Top returned to the opening frame. Video remains paused.
  • Static mode reports no video src and readyState 0. Menu/About navigation unloads the cinematic source. Next.js may retain the inactive video element with no source inside a hidden page.
  • The cart and carousel playback buttons were already absent in the actual repository. They were not reintroduced. Legacy cart tests now skip that removed subsystem while still validating the catalog.

Performance and validation

TypeScript, ESLint and the production build pass. Next.js generated all 16 expected pages/paths. Existing cinematic, menu, offers, reservation, reviews, enquiry, mascot and responsive-arrow scripts pass. The enquiry script was corrected to validate the configured sample contacts instead of asserting that they are empty. The first build encountered a cached Turbopack worker failure; a verified .next cache cleanup and an unrestricted build resolved it.

The production Chromium error/warning log was empty. Local HTTP requests returned 200 for the homepage and 206 for Range: bytes=0-1023, with exactly 1,024 bytes and the correct Content-Range. A cold HTTP inventory measured 25,645 compressed HTML bytes and 1,131,344 bytes for HTML-referenced JS/CSS/images. This is a partial asset inventory, not a browser initial-download waterfall: CSS-discovered fonts/backgrounds, dynamically selected video and subsequent lazy images are excluded. See HTTP inspection details.

Native scroll and reverse seeking were inspected without obvious blocking or page jumps. GPU usage, physical-device memory, quantified browser seek latency, CLS, main-thread traces and sustained frame rate were not measurable through the available browser controls. No 60 FPS, leak-free or WCAG conformance claim is made.

Known limitations and next steps

Physical iOS Safari/Android Chrome, Firefox, screen readers, OS-level reduced-motion changes and network throttling still need testing. Center/scene-aware cover cropping cannot retain the entire landscape composition on narrow phones. The desktop encode sits slightly above the suggested 20 MB decimal target to retain visual quality and seeking quality. Hosting must preserve byte-range responses; only the local server was verified. Existing restaurant contacts, story, prices and promotions remain sample/unverified configuration and need owner verification before launch. Real reservations, email delivery, authentication, checkout and backend persistence remain outside scope.
